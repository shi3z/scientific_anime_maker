# ピクセルアート教材 GIF の作り方

作るのは **`scenes.js` 1 ファイルだけ**。描画部品は `pixel.js`、書き出しと検査は `build_gif.py` がやる。

```
python3 build_gif.py scenes.js -o out.gif --title "題名"      # 検査 → 確認画像 → GIF
python3 build_gif.py scenes.js -o out.gif --lint-only         # 検査と確認画像だけ（速い）
```

どちらでも、ブラウザで開くと再生できる `out_preview.html` が書き出される（場面の切り替え・一時停止つき）。

**高解像度モード**: `--hires 4` を付けると、座標は 320x180 のまま 1280x720 で描き、文字はなめらかな等幅フォント、線・円はなめらかな線になる
（1 文字の幅は 4 のままなのでレイアウトは変わらない）。画像を読めるモデルに出来を確かめさせるときは必ずこれを使い、
`--frames-dir DIR` で各場面の 35% と 80% のコマを原寸で保存して渡す（縮めた画像では 3x5 ドットの文字や細い線を読み違える）。

必要なもの: Chrome/Chromium、ffmpeg、Pillow、日本語フォント（mac は標準で OK）。

## 手順

1. **題材を場面に分ける。** 1 場面 = 1 つの考え方。6〜8 場面、各 6〜10 秒、合計 40〜70 秒が目安。
   各場面について「見せる絵」「画面内の短い英語ラベル」「日本語字幕 1〜2 文」を先に決める。
2. **場面ごとにレイアウトを決める。** 画面は 320x180。上の 0〜11px は見出し帯（`title()`）。
   よく使う割り方: 左に図（x 0〜170）、右に式や説明（x 176〜316）。文字は 1 文字 4px なので、
   右半分 140px に入るのは **1 行 35 文字まで**。
3. **scenes.js を書く**（下の規約を守る）。
4. **式や数値を画面に出すなら、表示する文字列そのものを検算する。** 符号の書き間違いはレイアウト検査では見つからない。
   - 表示する式の文字列を定数にしておき、**同じ文字列**を `text()`/`matrix()` と `checkExpr()` の両方に渡す。
     `checkExpr('K1K2C−K3S', {K1, K2, K3, C: 1 - Math.cos(th), S: Math.sin(th)}, 定義から計算した正しい値)`
   - 正しい値は、表示とは独立に定義から計算する（例: 実際にベクトルを回して成分を読む）。
   - 別に書いた関数同士を比べるだけの検算は、画面の誤りを見つけられないので不可。
   - 検算は適当な値（単位ベクトルなら正規化した非対称な値、角度なら 0.7 など）で 2〜3 通り行う。
5. **`--lint-only` で検査し、出た問題をすべて直す。** 検査項目:
   - `ERROR` … JavaScript の例外（その場面は描けていない）
   - `MISSING GLYPH` … フォントにない文字。別の書き方にする（例: `√` → `SQRT`）
   - `OUTSIDE` … 文字が画面からはみ出している
   - `OVERLAP` … 文字同士が重なっている（ラベルの位置をずらす、行を増やす、表示時間をずらす）
   - `BADTEXT` … `undefined`・`NaN` などが文字として出ている（関数の引数の取り違え、未定義の値）
   - `COLOR AS TEXT` … 色コードが文字として描かれている（`matrix` や `segs` への渡し方の誤り）
   - `CHECK FAILED` … 検算が合わない（画面の式が間違っている）
   - `EXPR ERROR` … checkExpr に渡した式が読めない（書き方を evalExpr の規則に合わせる）
   - `NO CHECKS` … 検算がない
6. **`<out>_sheet.png`（各場面の途中 2 コマ）を目で見る。** 図と文字が重なっていないか、
   式の成分が枠からはみ出していないか、意図した順に要素が出ているかを確認する。検査は文字同士しか見ないので、
   **図と文字の重なりはここで見つける。**
   **直すときは、問題のある場面だけを書き直す。** 全体を書き直すと、直したつもりの場面が前と同じまま出てくることが多い。
   その場面のオブジェクトだけを取り出し、その場面の確認画像・検査結果と一緒に「この場面だけ」を書き直して差し替える。
7. 問題がなくなったら GIF を作る。サイズが大きければ場面を短く・少なくするか、2 本に分ける。

## scenes.js の規約

```js
const SCENES = [
  {
    name: '場面の短い名前（字幕帯の見出しに出る）',
    dur: 8,                                   // 秒
    draw(t) { title('0', 'SHORT HEADING'); /* t 秒時点の絵を描く */ },
    cap: t => t < 4 ? '前半の字幕。' : '後半の字幕。',   // 日本語。canvas には描かない
  },
];
```

- `draw(t)` の前に画面は背景色で塗りつぶされている。**毎コマ全部描き直す**前提で、前のコマの状態を持ち越さない。
- **同じ t なら必ず同じ絵**（`Math.random()` と `Date` は禁止。乱数は `rng(seed)`）。
- 重い計算（シミュレーションなど）は `SCENES` の外で一度だけ行い、結果を配列に入れておく。
- 動きは `t` の関数で書く: 出現は `ease((t - 開始秒) / 長さ)`、段階は `Math.floor(t / 間隔)`、点滅は `blink(t)`。
- canvas 内の文字は **短い英語（大文字になる）・数式・記号**。説明文は字幕 `cap` に日本語で書く。
- 1 場面の中で要素を順に出すときは、字幕も `t` で切り替えて、いま光っているものを説明する。

## pixel.js の部品（すべてグローバル）

**画面と色**: `W=320, H=180`、`ctx`、色 `C.bg C.panel C.line C.dim C.ink C.ink2 C.gold C.gold2 C.blue C.red C.teal C.purp C.pink C.green C.yellow C.empty C.dark`。
`mix(色a, 色b, 0..1)` で中間色。

**図形**: `R(x,y,w,h,色)` 塗り矩形 / `box(x,y,w,h,塗り,枠)` / `frameBox(x,y,w,h,枠)` / `dotted(x,y,w,h,色)` /
`line(x0,y0,x1,y1,色)` / `circ(cx,cy,r,色)` 円周 / `disc(cx,cy,r,色)` 塗り円 / `ellipse(cx,cy,rx,ry,枠,塗り)` /
`arrow(x0,y0,x1,y1,色,ラベル?)` / `arrowR(x,y,色)` `arrowD(x,y,色)` 小さな三角 /
`wire(点列,色)` と `packets(点列,色,t)` で配線と流れる粒 / `bar(x,y,w,h,割合,色)` 進捗バー /
`plot(x,y,w,h,[[x,y],...],[xmin,xmax],[ymin,ymax],色)` 折れ線 / `hvec` `vcol` ベクトルを色の帯で /
`noiseTile(x,y,w,h,seed)` ノイズ模様 / `waveform(x,y,w,振幅,t,色)` 音声波形。
`sprite(x,y,文字列の配列,{文字:色},拡大率=1,左右反転=false)` ドット絵（'.' は透明）。人物・船・動物などに使う。

**文字**: `text(文字列,x,y,色,'left'|'center'|'right')`（幅を返す）/ `textWidth(文字列)` = 文字数×4−1 /
`segs(x,y,[['文字',色],...])` 色違いを横に並べる / `title(番号,見出し)` 上部の見出し帯。
文字は 3x5 ドット。行送りは 8〜10px。小文字は自動で大文字になる。
使える記号: `+ - × · − ± = ≈ ≤ ≥ < > → ← ( ) [ ] { } / % ^ ' ′ ² ³ ᵀ ° √ ∝ ∥ ⊥ ∞ : ; , . ! ? _ | # * @ & ~ "`
ギリシャ文字: `α β γ δ ε θ κ λ μ π ρ σ τ φ ψ ω ħ Δ Σ Φ Ω`。**これ以外（日本語を含む）は描けない。**

**行列**: `matrix(x,y,cells,列幅,行高=12)`。`cells[r][c]` は `'文字'`、`['文字', 色]`、`[['文字',色], ['文字',色], ...]` のどれでもよい。
**列幅 ≥ 最長成分の文字数×4+6** にしないと隣とくっつく。戻り値は全体の幅。`brackets(x,y,w,h)` は括弧だけ。

**3D**: `CAM = {ox, oy, scale, yaw, pitch}`（原点の画面位置など。場面ごとに設定）/ `P3([x,y,z])` → 画面座標 /
`line3(a,b,色)` / `arrow3(a,b,色,ラベル?)` / `axes3()` / ベクトル計算 `V3.dot V3.cross V3.add V3.mul V3.norm`。
視点を少し揺らす（`CAM.yaw = 基準 + Math.sin(t*.3)*.2`）と立体感が出るが、GIF は重くなる。

**その他**: `clamp ease lerp blink(t,hz) rng(seed)`。

**検算**: `checkExpr(表示する式, 変数, 正しい値, 説明?)` / `evalExpr(式, 変数)` / `check(説明, 真偽)` / `near(a, b)`。
scenes.js のトップレベル（SCENES の外）で呼ぶ。`evalExpr` が読める書き方: 数字、変数（`vars` のキー。長い名前が優先）、
`+ - − × · * / ^ ² ³ ( )`、等式（`F2 = F1×L1/L2` なら右辺を計算）、関数 `COS SIN TAN SQRT`（`COSθ` のように引数の括弧は省略可）、並べると掛け算（`2K1K2`）。
表示用の飾り（`[K]×` のような記号）は式として読めないので、検算するのは成分や数値の部分だけにする。

## レイアウトの注意（よくある失敗）

- ラベルは**線や図形の上に置かない**。矢印のラベルは `arrow(..., ラベル)` の自動配置を使い、重なるなら自分でずらす。
- 見出し帯（y 0〜11）の下は y 16 から使う。字幕は GIF 側で下に付くので canvas の下端まで使ってよい。
- 行列の成分や式の長さを `textWidth` で確かめてから置く。右端 x 316 を超えない。
- 2 つのベクトルが同じ向きになる瞬間があると、ラベルが重なる（検査で出る）。角度の開始値や範囲を調整する。
- **図の座標は直書きしない。** 場面ごとに少数の変数（支点の x、板の y、腕の長さなど）を決め、部品・ラベル・寸法線の位置はすべてそこから計算する。
  位置を別々に直書きすると、部品どうしがずれる（寸法線が支点に届かない、重りが板から浮く）。
- **部品どうしの関係は数値で検算する。** 「箱の下端 = 板の上面」「L2 の右端 = 箱の中心」などを `check('説明', near(a, b))` で書く。
  draw の中で呼んでよい（失敗はその場面の CHECK FAILED として報告される）。画像を見る確認では数ドットのずれを見逃すので、こちらが本命。
- 各場面に `expect: ['...']` として「80% の時点でこうなっているはず」の項目（4〜8 個、目で確かめられる具体的な文）を書いておくと、
  画像で出来を確かめるときの確認項目になる。
- 情報を詰め込みすぎない。1 場面に式は 3〜4 行まで。多ければ場面を分けるか、時間で出し分ける。
- **長い式は短い記号に置き換えてから並べる。** 例: `C = COSθ, S = SINθ, T = 1 − COSθ` と画面に定義し、
  成分は `C+KX²T`、`KXKYT−KZS` のように書く（1 成分 9 文字以内）。3x3 行列が収まる目安は
  **列幅 × 3 + 6 ≤ 使える幅**。置く前に `最長成分の textWidth + 6` から列幅を計算し、画面幅（右端 316）に入るか確かめる。
- 行列の横に説明を置くと幅が足りなくなりやすい。行列は画面上半分に単独で置き、説明は下に置く。
